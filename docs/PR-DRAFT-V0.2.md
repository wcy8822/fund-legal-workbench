# 接入意见改写：固定资料、草稿修订与人工采纳

状态：供私有仓库 Draft PR 使用的正文。当前没有远端 PR；V0.2 实现尚未运行验证。

## 为什么需要

同一条法务意见常要分别写给法务、业务和交易对方。此前工作台能记录风险与建议，但缺少带版本和依据的表达整理入口，也不能保存改写草稿与采纳历史。使用者需要反复复制条款、解释背景，且不容易分辨文字调整是否改变了原有立场。

## 本次改动

- 在审核意见中加入“改写 / 查看表达”，选择读者和语气。
- 固定原意见、原始及当前版本、相关条款、已有法源和未知项；保存完整提示词与资料摘要。
- 普通材料准备提示词并支持手工草稿；预设虚构问题提供明确标记的离线表达示例。没有外部模型调用。
- 草稿与人工采纳追加保存。原风险、建议、引文、原件和问题状态保持原记录；采纳表达不会关闭意见或批准文件。
- 人工采纳要求核对含义并填写说明；对方批注另行确认披露范围。资料变化后旧任务保留，采纳需基于新资料重新准备。
- 已采纳表达可以单独复制到 Word。内部 DOCX、PDF、MD 清单保留原意见，并附匹配版本的有效表达；对外清洁合同不带内部表达和说明。
- 采纳增加项目审查版本，令此前文件批准需要重新复核。其他用途的表达可以并存，真实版本、依据和审查状态变化仍触发过期。

## 验证状态

用户要求“先不验证”，本轮没有启动应用、执行语法检查、自动测试、浏览器验收或模型评测。

新增 `tests/test_opinion_rewrites.py` 包含证据不覆盖、明确人工确认、过期拒绝、项目边界、追加式历史、交付批准失效、不同用途共存及内部外部内容隔离等回归用例，**尚未执行**。V0.1 的 51 项 Python 测试和 36 项前端断言只保留为历史记录，不能证明当前分支通过。

新增数据库结构采取追加建表方式；旧数据升级、真实浏览器操作与 Word 使用路径仍待用户恢复验证安排后检查。

## 当前范围与后续

本版是单人本机虚构数据开发版。Gemini／Claude 适配、公司审查标准与项目事实确认、通用合同首审、明确基准的来稿复核、审批材料生成仍未在本次接入；本机人工确认不代表企业审批权限。

继续保持四个项目入口和现有公司接口范围，不自动合并或公网部署。运行安排恢复后，优先执行新增证据／采纳回归及相关既有交付门槛，再核对浏览器和 Word 路径。
