# V0.2 意见改写：从一条意见到可采用的表达

日期：2026-11-21。应用标识：`0.2.0-dev`。状态：实现代码已写入，按本轮要求暂不运行验证；没有模型调用、效果评测或企业权限验收结果。

## 一句话结论

在原有“审核意见”中加入一个用途明确的动作：选定意见和读者，固定本次条款、版本与依据，准备提示词或离线示例，保存修改草稿，再由法务确认并留下采用记录。

## 1. 这次具体做到哪里

| 离线演示 | 仅对内置虚构样例中预设的付款、通知、审批附件问题提供示例 | 明确标记为非模型文字；不作为 Gemini／Claude 能力或效率结论 |

| 人工采纳 | 对最新草稿进行事实／含义确认，填写说明；对方批注额外确认披露范围 | 记录的是本机单人采用行为，不是公司审批、签署许可或对外发布 |
| 历史记录 | 原意见、草稿和采用记录分开保留 | 不覆盖原风险、建议、引文或处理状态；不自动关闭旧问题 |
| 内部清单 | DOCX、PDF、MD 内部审核清单可附有效的已采用表达 | 保留原建议在前；对外清洁合同稿不混入改写表达、含义说明或采用记录 |

上述是代码承担的行为，尚未通过本轮实际执行证明。V0.1 的历史通过记录不能覆盖这次新增代码。

## 2. 使用路径

这些步骤供后续恢复运行安排时使用，本轮没有要求使用者现在验收。

1. 打开虚构项目，在“审核意见”选定一条最新处理记录，点击“改写 / 查看表达”。
2. 选择阅读对象、表达语气和“本次怎么准备”，点击“准备这次改写”。默认准备资料与提示词；符合虚构样例条件时，可以主动选择离线演示。
3. 查看本次使用的原意见、合同版本、条款及依据。原意见来自历史版本时，额外关注它与当前版本的差异；不能只看稿件名称。
4. 查看或输入草稿。对照原意见，写明保留了哪些意思、改了哪些表达、是否提出实质变化。系统提供的文字差异不证明法律含义完全相同。
5. 点击“保存为新草稿”。需要继续改时再保存一个版本；原草稿和原意见继续保留。
6. 采纳前确认最新草稿及含义，填写说明并勾选人工确认，然后点击“人工采纳此草稿”。对方批注还需要检查内部底线、审批讨论、风险评分等不应披露的信息。
7. 原意见卡下独立显示“已采纳的表达”，可以复制选定用途的文字到 Word。复制对方文字不附带内部含义说明；复制本身也不构成对外稿批准。

如果资料在此期间变化，任务显示需要重新准备。保存过的草稿仍可查看，但不能直接采纳为当前结果。重新准备后，由法务重新核对内容。

未保存的编辑只暂存在当前页面内存中，不使用浏览器持久存储。应先保存草稿再关闭或刷新浏览器；本轮未运行界面验证，不能保证所有导航和错误路径已经妥善处理，也不能声称可跨刷新恢复。

生成内部审核清单时，仅附上与导出版本一致且未过期的已采用表达；同一根问题、同一用途选取最新有效记录。该段明确标“仅作内部记录，不替代原意见，不代表放行”，包含表达正文、含义说明、采用说明和记录 ID，原建议仍保留在前。

同一条意见可以分别采纳内部法务版、业务沟通版和对方批注版。只增加采用表达时，不使已有表达或待采纳草稿互相过期；只有合同版本、原意见、处理状态、依据等审查资料发生变化，才需要重新准备。已过期表达仍在历史中，但不自动附入新的内部清单。DOCX、PDF、MD 的这条新增导出路径均未在本轮运行。对外清洁合同正文不受改写表达影响，真实 Word 编辑仍另行产生新合同版本。

## 3. 资料快照与状态

### 固定资料

| 信息 | 用途 |
| --- | --- |
| 项目 ID、法域、判断时点与审查版本 | 明确项目范围，并识别审查资料是否变化 |
| 当时已采用表达数量 `expression_revision` | 区分只新增表达与实际依据变化，让不同读者版本可并存 |
| 合同 ID、标题与当前版本指针 | 明确本次对应哪一份合同、哪一版 |
| 原意见、根问题、原始引文与原状态 | 留下改写前的事实及处理位置 |
| 原始／当前版本 ID、SHA-256、当前条款 | 对照历史与当前材料，不动态替换本次资料 |
| 已引用法源记录 | 保留已有出处和核验状态，不新增或编造引文 |
| 解析警告、未知项 | 明确材料不足、公司口径缺失及未覆盖范围 |
| 提示词版本、内容与资料摘要 | 保留本次如何组织资料的记录 |

任务使用 `prepared`、`draft`、`adopted` 三个状态：只有资料和提示词时为 `prepared`；存在草稿但未采纳时为 `draft`；有人工采用记录时为 `adopted`。`stale` 是另行计算的资料过期标记，不能当成一次新的审批状态。

任务、草稿和采用记录设计为追加保存，由数据库阻止普通更新和删除；采用记录指向确切草稿。原审核意见及合同原件仍由既有记录负责。任务不会调用意见关闭或交付批准流程。

### 什么情况下需要重新准备

创建任务限于当前可处理的最新未结根问题。该问题可以源自历史版本，但任务必须固定实际当前版本及其对应条款，并提示历史与当前的不一致。当前版本是签署件、待 OCR、不能解析、无正文或无法定位对应条款时，不生成可采纳任务。

在采纳时重新判断项目和合同是否归档、当前版本是否变化、根问题是否已经承接或状态变化、原意见是否变化，以及项目审查资料是否变化。项目级判断会排除仅由采用表达引起的审查版本增长，所以多种读者版本可以连续采纳和并存。同一项目其他实际依据或审查决定变化，仍可能使已准备任务需要重新处理。

采用意见表达会增加项目审查版本，因此此前对外文件批准需重新复核。这是为避免“批准后审查记录变了，但仍沿用旧批准”。采用表达不修改问题的开闭状态，也不会修改 Word 原件或生成新合同版本。

| 变化 | 改写任务与已有表达 | 先前对外文件批准 |
| --- | --- | --- |
| 仅新增另一条或另一种用途的采用表达 | 原证据未变时可继续使用；同一用途导出取最新有效记录 | 需要重新复核 |
| 合同版本、原意见、状态或依据等实际审查资料变化 | 需要重新准备，历史保留 | 需要重新复核 |

## 4. 本地接口与存储

新接口属于本机单人工作台。每次查询和写入按项目及问题／任务归属查找，不直接接受存储路径；它们没有被扩展为公司集成接口，也不构成企业多用户授权。

| 方法及路径 | 作用 |
| --- | --- |
| `GET /api/projects/{pid}/issues/{iid}/rewrites` | 获取可创建状态、离线演示可用性、任务与采用历史 |
| `POST /api/projects/{pid}/issues/{iid}/rewrites` | 固定资料，按读者、语气及模式创建任务 |
| `GET /api/projects/{pid}/rewrite-tasks/{tid}` | 获取固定资料、草稿历史、采用记录及当前过期状态 |
| `POST /api/projects/{pid}/rewrite-tasks/{tid}/drafts` | 追加手工草稿与含义说明 |
| `POST /api/projects/{pid}/rewrite-tasks/{tid}/adopt` | 经人工确认后采用最新草稿并记录说明 |

创建参数为 `audience`（`internal`／`business`／`counterparty`）、`tone`（`concise`／`gentle`／`firm`）、`mode`（`prepare`／`demo`）。当前没有外部模型模式或隐式网络请求。

保存草稿参数为 `text`、`meaning_notes`。采用参数为 `draft_id`、`human_confirmed`、`meaning_confirmed`、`external_safe_confirmed`、`note`；对方批注要求额外的披露确认。文字上限为 12,000 字符，含义说明和采用说明各为 4,000 字符。它们只是输入边界，不代表适合将长篇合同塞入单条意见。

三张新增表分别保存任务（`rewrite_tasks`）、草稿（`rewrite_drafts`）和采用表达（`issue_expressions`）。新增结构使用 `CREATE TABLE IF NOT EXISTS`，不执行旧意见字段更新；数据库首次启动与已有数据升级路径本轮均未运行验证。审计记录关联创建、保存和采用等操作。SQLite 的单人本地部署和固定本机操作者标识，尚不具备真实公司身份、岗位权限或审批职责的证明能力。

`docs/openapi.json` 保留此前 V0.1 生成快照，三个公司接口未在本轮扩展。此文件尚不包含新路由；恢复启动后，实际服务的 `/openapi.json` 将展示当时注册的本地接口。本轮没有为生成文档而启动应用。

## 5. 已有能力与仍待实现

本次复用项目、合同版本、法源、意见根问题、审计和批准失效机制。原来的演示审查仍是确定性规则，不能等同于通用合同首审或多轮来稿复核。

待实现的部分包括：真实模型适配及其数据授权、项目事实确认界面、经批准的公司审查标准库、合同首审动作、明确基准的来稿复核、审批材料动作、Word 插件和公司审批系统连接。已采纳的表达也不会自动成为公司通用口径。

真实项目试点前仍需完成原有 V1 门槛：公司授权、厂商数据处理与留存、项目权限隔离、审计和备份恢复等。对方批注的人工确认属于本地操作记录，不能替代公司批准链。

## 6. 后续验证清单（本轮未执行）

仅在用户恢复验证安排后执行：

1. 原件与原意见字段不被改写或采纳覆盖，旧问题不自动结案。
2. 普通资料准备任务没有模型输出；演示模式限于明确虚构场景。
3. 手工草稿逐版追加；人确认及说明缺失时不能采纳；已采用任务不能被另一稿覆盖。
4. 改变当前版、承接问题、改变状态或更新项目审查资料后，旧任务不能直接采纳。
5. 采纳使先前交付批准失效，未批准件仍无法从公司接口下载。
6. 跨项目读取与写入被拒绝；归档及签署件限制有效。
7. 界面在请求错误、过期提示、历史切换与关闭面板时妥善处理未保存输入；对方文字复制不带内部说明。
8. 内部 DOCX、PDF、MD 清单保留原意见并只附匹配导出版本的最新有效表达；旧版、过期表达及内部说明不误入对外清洁合同稿。
9. 同一意见连续采纳不同读者版本时，各自保留且不互相过期；其间实际依据或处理状态变化仍会阻止旧草稿采纳。每次采纳均继续使旧文件批准失效。

不能将后续用例清单、已写入的测试代码、源码阅读或文字差异称为实际测试通过、模型效果通过或浏览器验收通过。
