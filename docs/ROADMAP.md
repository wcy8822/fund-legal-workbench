# 实施清单与验收门槛

版本：0.1 · 2026-11-21

## 一句话结论

先让一名法务用虚构项目把版本与问题闭环走通，再通过公司授权、权限隔离和恢复演练进入受控试点，最后对接公司系统。

下列条目均为验收要求。未在测试记录中提供实测证据的事项不得标记完成；代码存在、页面展示或计划排期均不等于通过验收。

## V0：本地演示

范围：单用户、仅本机、虚构合同；无真实公司连接、无公开部署；默认无需外部模型密钥。

| 工作包 | 实施内容 | 验收证据 |
| --- | --- | --- |
| 启动与种子 | 一条命令启动同源前后端；明确虚构标识；新项目只有合同/审核意见/法源/交付物 | README 命令实际启动；页面可点通；种子可重复创建且不覆盖已有项目 |
| 合同台账 | 新增/查询/更新标题与相对方/可恢复归档；区分初稿、对方版、修订稿、定稿、签署件 | 可查历史版与当前版；归档后可恢复；无普通硬删审查与签署件入口 |
| 不可变原件 | 每次正文修改新建版本；原件摘要与操作记录；可下载指定历史文件 | v1 上传后再上传 v2/v3，v1 取回字节和 SHA-256 不变；同名文件也不覆盖 |
| 差异 | 首版文本比较；Word 修订/复杂内容提示；扫描 PDF 标待 OCR | 明确显示 10→5→10；通知对象与附件变化可见；不承诺 Word 修订重建 |
| 意见 | 固定到具体合同版本、条款、引文；包含风险、建议、待确认、依据与状态 | v2 建问题，v3 上传后问题仍存在且未自动结案；人工关闭留说明和操作记录 |
| 离线建议 | 演示规则与模型适配边界；候选不排序 | 无密钥可运行；UI 明确不是 Gemini/Claude 实测；AI 无批准或关闭权限 |
| 法源 | 官方入口、手工录入、分类/法域/时点/核验；种子法源准确 | 可从第 8.2 条问题打开真实官方民法典第 565 条出处；不生成虚构检索结果 |
| 交付 | 内部审核清单、清洁阅读稿；生成后检查并人工批准 | 未批准件经对外交付 API 下载被拒绝；批准限定具体文件摘要；内部意见不进入清洁稿 |
| 公司接口骨架 | 按权限列项目合同、导入版本、下载批准件；OpenAPI；项目范围、审计、幂等 | 跨项目对象引用被拒绝；相同幂等键/相同请求不重复建版；同键不同正文被拒绝；不返回存储路径 |
| 验证与交接 | 最小自动测试、人工点击脚本、格式能力表、架构和调研记录 | 测试输出注明环境和真实结果；未测试项写明；能交给本机 Codex 继续执行 |

边界验收还须覆盖：当前版回退后再上传、上传时关闭“带入意见”、对外稿生成后再新增意见、批准后切换当前版再切回、同幂等键传不同类型/文件、未批准实际文件的内部复核预览。跨项目对象隔离与接口 scope 测试只证明所测公司入口的保护；不得据此宣布本机单人工作台已具备企业权限系统。

### 首轮场景的通过标准

建立虚构投资项目 → 上传初稿 → 上传对方版 → 比较 → 给第 8.2 条挂有准确官方法源的意见 → 上传新版 → 确认期限恢复但通知对象及审批附件问题仍未解决 → 生成内部清单与对外清洁稿 → 未批准不能从对外接口取件 → 人工检查/批准后才可下载。

“对外清洁”仅表示去掉内部批注、修订和不应携带的元数据后的交付状态，不表示合同风险均已解决。若法务决定带着未决事项发出谈判稿，应在内部批准记录说明用途和接受的未决问题；签署用定稿应另有更严格门槛。V0 不自动把谈判稿变成可签署定稿。

### V0 明确未做

企业 SSO 和多用户权限；恶意文件隔离/OCR 服务；复杂 Word 排版与修订保真；PDF 签章或数字签名真实性验证；商业法源接口真实调用；模型效果实测；公司环境安装验收；生产备份和恢复 SLA；自动发送、自动签署和全量法规更新。

## V1：受控试点

建议首个试点限制为 1 名法务、少量已授权项目；数据在获批位置存放。启动前必须由公司指定负责人完成以下门槛，不能因用户有合同访问权就自动视为可把合同发给外部模型。

| 门槛 | 完成条件 | 失败时处理 |
| --- | --- | --- |
| 公司授权与用途 | 明确试点数据类别、处理目的、人员范围、存储位置、保留期限及准入批准 | 继续使用虚构材料，不导入真实项目 |
| 身份与项目权限 | 接公司身份或受控账号；项目 read/write/review/approve 权限；服务账号最小范围；撤权即时生效 | 未通过越权测试不开放多人/内网使用 |
| 数据留存与厂商 | 核验模型、OCR、法源供应商的训练用途、留存/删除、地域与子处理者；必要合同已签 | 保持离线演示；不得绕用个人订阅代替机构许可 |
| 文件输入 | 按文件类型和大小限制；解析沙箱/资源上限；病毒检查策略；扫描与受保护文件明确报错 | 文件可隔离归档，不能将解析失败当无风险 |
| 审计 | 操作主体、项目、对象版本、时间、动作、决定及摘要；下载/批准/撤销均可追溯；敏感正文不进通用日志 | 不能追溯批准人与产物时不得对外取件 |
| 备份与恢复 | 数据库和原件一致备份；在独立目录恢复并重算摘要；检查意见、批准状态和权限；记录耗时与损失窗口 | 恢复失败不接纳真实项目；不以“有备份目录”算验收 |
| Word/PDF 实际工作流 | 使用获批样本评估编号、表格、脚注、交叉引用、修订、批注和签章边界；法务签认转换限制 | 继续下载原件回 Word 操作，不用重建稿替代签署原件 |
| 模型盲测 | 按 [MODEL-EVALUATION.md](MODEL-EVALUATION.md) 固定输入与金标准，同题匿名评分与计时 | 引文不可核验、重大遗漏或人工复核负担过高时不设为默认 |
| 法源检索 | 明确商业授权/配额；只传去标识化问题；请求预览；超时与无结果可区分 | 回退官方跳转与人工录入，不伪造答案 |
| 用户价值 | 观察找到正确版本、复核遗留问题、确定可外发文件的用时和误操作；有人工基线 | 不以生成文字量或调用次数代替生产力指标 |

试点结束产出：获批范围、实际问题清单、实测指标、已关闭风险、仍需人工承担的步骤、下一轮范围。只对试点中已经验证的能力作承诺。

## V2：公司集成

| 工作包 | 验收门槛 |
| --- | --- |
| 企业文档库 | 与真实文档库 API 对接；版本保留与项目授权一致；历史原件可取回；升级/回滚演练成功 |
| 三个公司入口 | 合同列表只返回调用者有权项目；导入新版本支持授权、幂等、摘要与重试；下载只返回指定已批准交付物；拒绝原件存储路径直出 |
| 生命周期 | 审批撤销、定稿后新版本、签署归档、授权撤销等状态变化可追踪；批准不能随版本漂移 |
| 审计与安全 | 集中审计、防篡改保存、下载水印策略、密钥轮换、依赖/漏洞治理、跨项目越权测试和事件响应 |
| 业务连续性 | 按公司要求确定 RPO/RTO；灾备恢复、权限恢复、证据链完整性和容量测试通过 |
| 模型与法源运行 | 调用成本限制、超时退避、结果校验、提供者切换、引用过期/规则更新提示；人工复核继续保留 |
| 运行验收 | 指定负责人接收运维文档、变更与回滚方案；日志/监控可定位失败；公司系统对接通过联调 |

## 下一步优先事项

V0 完成后，优先安排实际法务以虚构合同进行一次从 Word 到交付的操作演练，记录三处最费时或最容易误判的位置。先用这份证据决定 V1 功能优先级；同时走公司授权与数据边界确认，未经门槛不转真实项目。

## 思维导图结构

V0：虚构项目与链路 → V1：授权、权限、恢复、Word 与模型实测 → V2：企业存储、公司 API、集中审计和运行保障。
