# V0.3 检索架构：公开依据、项目资料与浏览器补位

文档研究日期：2026-11-21。本文是接入决策与后续边界，**不代表已经连接任何第三方 MCP、调用搜索 API、访问公司系统或完成运行验证**。本轮遵循“先不验证”：没有为本文安装服务、启动浏览器、运行测试或读取用户电脑资料。应用实际实现范围以本轮 README 和对应实现说明为准。

**结论：在“法源”内提供统一的查依据动作，优先复用本项目已有资料；公开检索只发送经人确认的抽象法律问题，经授权的公司资料走独立入口，浏览器用于明确站点的补位。** 检索提供可核对的材料，法务决定适用性并采纳为依据。

## 1. 产品动作与资料边界

保留合同、审核意见、法源、交付物四个入口。“查依据”可从法源进入，也可承接一条审核意见。任务固定项目、法域、判断时点与问题；需要查询最新状态时另记本次检索时间，不能用今天的检索时间代替交易的法律判断时点。

一次任务分开处理三类资料：

| 资料范围 | 优先动作 | 结果应标明 |
| --- | --- | --- |
| 本项目资料 | 搜已导入合同版本、原意见、已记法源与审查记录 | 项目、合同、版本、条款或记录 ID、当前/历史状态；扫描或解析失败的文件未完整覆盖 |
| 公开法律依据 | 专业授权接口或官方页面；通用搜索发现原文链接；必要时在明确官方站点用浏览器 | 来源类别、法域、发布主体、原文链接、准确引文、公布/施行时间、效力状态与核验时间 |
| 公司已授权资料 | 采用现有文档库/系统接口，遵循调用者权限；限定项目或获准资料库 | 原系统、记录 ID、版本/更新时间、发布与批准状态、适用范围、返回内容的权限边界 |

内部模板、往例和口径可减少重复工作，但不能自动标成有效公司制度，更不能代替法律依据。旧审批同意某笔交易，也不自动授权另一笔交易。系统信息先限于本工作台的版本、连接器是否配置、上次检索状态等诊断元信息；不把读取环境变量、整个磁盘或其他已登录系统作为通用检索功能。

公开查询字段只容纳抽象法律问题。例如“合同解除通知的到达对象及送达时点，应如何核对法律依据”。不拼接项目名、客户名、合同全文、内部意见或交易参数。人工确认用于确定本次输入可外发；字符串过滤只能辅助提示，不能宣称已经自动完成脱敏。

## 2. 可以复用的成熟能力

### 2.1 Tavily：通用搜索与原文提取候选

Tavily 官方提供远程 MCP，地址为 `https://mcp.tavily.com/mcp/`；支持 OAuth 或 API key。其官方 keyless 文档还提供无需账号与密钥的 Search/Extract 路径：请求携带 `X-Tavily-Access-Mode: keyless`，可用于 REST API 和该 MCP。该方式免费但有限流，文档未给出固定的匿名数值配额；Crawl、Map、Research 需要 API key。不能把“公用 MCP”理解为无限免费或已经通过公司的数据留存审查。[T1][T2]

对于当前 FastAPI 单体，先写可替换的 REST 适配器即可，暂不必引入独立 MCP 运行服务。标准 Search 为 `POST https://api.tavily.com/search`，使用 `Authorization: Bearer <API key>`。可选字段包括 `include_domains`、`include_domains_mode`、`include_answer`、`include_raw_content`；`restrict` 只保留指定域名，`prefer` 仍可能返回其他网站。建议关闭生成答案，用官方域名范围获取候选 URL，再核对原文。[T3]

本项目若选择“显式启用 + 环境变量密钥”的接入方式，这是方便控制调用主体和停用的实现选择，不是声称提供方完全没有无密钥模式。默认关闭网络适配器，页面和审计区分“未调用”“候选结果”“原文已读”“人工核验”。公开网页研究也不等于应用适配器调用成功。

### 2.2 Brave Search MCP：可替换的第二搜索供应商

Brave 官方 MCP 需要 Brave Search API key，提供网页搜索及时间范围过滤。其本地 HTTP 模式默认绑定 `127.0.0.1`，上游明确该 HTTP 端点没有身份认证，不能直接当作公司可共享的公开服务。若将来接入，优先放在工作台服务端受控调用，保持供应商可替换，不把密钥交给前端。[B1]

Tavily MCP 与 Brave MCP 上游许可文件均为 MIT；该许可涉及适配代码，不等于商业 API 无配额、数据库内容可无限保存或可自由再分发。[T4][B2] 本轮没有比较实际中文法律检索召回率、服务延迟、费用或授权条件。

### 2.3 Microsoft Playwright MCP：官方页面与已授权系统的补位

Playwright MCP 官方实现可连接持久浏览器资料，扩展模式还可利用既有浏览器标签页及登录状态。这样可以处理部分没有接口的页面，但浏览器继承的登录身份不等于本应用已经具备项目授权。[P1]

上游明确说明它不是安全边界；`allowed-origins` 等限制不能覆盖重定向。把任务写成“只读查询”也不会自动撤掉点击、提交或下载能力。因此本项目未来若启用，应限定站点和任务、使用专门的浏览器资料与最小权限账号，并在应用层约束允许的动作。遇到登录、验证码、付费授权或禁止自动化的限制，停留在明确的手工接续步骤，不绕过限制。[P1]

浏览器只有在受支持接口不能完成明确任务时启用。它不负责遍历电脑、猜测现有登录账号或把任意页面当成可信指令。外部页面、合同和检索结果都只是待分析数据；其中要求执行命令、泄露资料或更改授权的文字不能成为工具指令。

### 2.4 Microsoft Graph / SharePoint：遵循源系统权限的内部检索候选

Microsoft Search API 的委托身份检索遵循已登录用户对源系统资料的访问权限；不能因为建立了搜索索引就跨过原文件的访问控制。不同 API 的许可范围不同：综合 Search API 与指定 drive/folder 的 `driveItem/search` 不能共用一个笼统的“最小权限”声明。后者的委托读取场景可使用 `Files.Read`，其应用权限场景要求更广的权限，并明确不支持 `Sites.Selected` 应用权限。[M1][M2]

若公司使用 Microsoft 365，优先评估委托身份和指定项目资料位置，核对所选 API 实际支持的范围。不能仅靠在宽权限应用的查询中增加项目关键词来证明项目隔离。结果显示、原文取回、缓存与后续模型上下文都需持续遵循来源权限；人员离职、项目移交或撤权后，旧缓存也不能继续向其提供原文。

当前没有公司租户、资料库、账号范围或授权说明，因此这里只保留连接器方案，不探查账号，不承诺已能检索公司材料。

### 2.5 官方 Filesystem MCP：选择性目录读取

官方参考实现支持显式目录范围及 `--read-only`；只读模式不注册修改工具，并建议结合操作系统只读挂载。可用于用户明确选定的本机资料目录，不能据此给整个用户目录开放访问。[F1]

MCP 是调用协议，本地服务本身仍按其操作系统进程权限运行；配置允许目录是工具合作遵守的限制，实际隔离还需要操作系统边界。[S1] 文件读取服务也不会自动获得可靠的 Word 修订解析、PDF OCR 或法律文档版本语义。首版优先搜索已经导入工作台、能够按合同版本追溯的解析文字，暂不对电脑另建全文索引。

## 3. 证据如何进入审核意见

“找到链接”“读到原文”“确认效力与适用性”分别记录。通用搜索摘要、自动生成答案和网页排名只帮助发现材料；不能直接把摘要填成法条引文，也不能根据网站更新时间认定法规生效时间。

建议每次任务保留以下数据，并通过引用关联到原有法源快照，不覆盖历史记录：

| 记录 | 最小内容 | 用途 |
| --- | --- | --- |
| 检索任务 | 项目、抽象法律问题、法域、判断时点、当前查询/历史适用目的、去标识化确认 | 固定本次工作边界 |
| 检索执行 | 连接器、实际调用与否、时间、查询范围、结果数、错误或限制原因 | 说明覆盖到哪里，以及哪里没查到 |
| 候选材料 | 原文 URL/源系统记录 ID、题名、摘要、发现途径 | 待核对；与正式引用分开 |
| 证据快照 | 原文片段及位置、主体、类别、版本、公布/施行/失效信息、核验时间与说明 | 支持可复核引用；受授权限制的全文不默认复制保存 |
| 人工采纳 | 采用的快照 ID、对哪条意见适用、人工说明、仍未确定的事项 | 将检索材料转化为具体审查依据 |

自动系统可给出“找到疑似新版本”“公开原文无法访问”“缺少生效信息”等提示。不能因结果列表为空写成“不存在法律/案例”，也不能因检索成功就宣布“已查到目前全部最新规定”。只有发布时间晚的新闻、修订草案或尚未施行文本时，应保留各自性质，不替代判断时点已有效的规则。

复查发现依据变化时，新增快照并提示相关意见需复核；旧快照仍解释原审查当时依据什么。采纳新依据应接入现有审查版本更新与交付批准失效逻辑，不能自动结案或自动批准对外文件。普通公开裁判、参考案例、指导性案例、规范性法律文件和公司制度的类别持续分开。

## 4. 分阶段落地

**V0 本机演示：**先把检索任务、官方入口、本项目资料查找、手工候选录入及人工采纳串起来。可保留默认关闭的通用搜索适配器；演示候选明确标记。连接器目录显示的是“文档证实有该能力”，不伪装成已经获授权或已连通。本轮不执行调用与运行验证。

**V1 受控试点：**公司确认可处理的数据和厂商条款之后，在一组虚构法律问题上核对原文命中、引文准确、效力时点、重大遗漏及法务复核耗时；选定一个搜索供应商和一个内部资料范围，再做真实权限、缓存撤权、审计与备份恢复验收。浏览器单独评估，账号范围与操作范围不能隐含在模型提示词里。

**V2 公司集成：**补充经授权法律数据库、公司文档库和审批系统连接器；实际读取公司审批状态时仍保留来源记录。对外下载继续走现有项目授权和人工批准接口，不暴露存储地址，不把检索工具升级为外发或自动审批工具。
