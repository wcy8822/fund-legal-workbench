## 为什么需要

审查意见需要同时找回项目已有材料和最新或历史时点适用的公开依据。直接把合同或内部问题发给搜索服务会超出项目数据范围；把搜索摘要当成准确法条，又会使后续意见缺少可靠出处。原有法源台账能登记来源，但没有固定查询条件、执行结果和人工核验的关联记录。

## 本次改动

- 在现有“法源”页加入本项目资料搜索、独立的公开问题查询与连接范围说明，维持四个项目入口。
- 本地仅搜索当前项目已导入合同文字、意见、法源与采用表达，可包含历史，提示未解析/OCR范围；不查询公司账号或电脑目录。
- 公开问题要求去标识化确认，默认只准备官方跳转。可选 Tavily REST 适配器默认关闭，支持 keyless 或服务端 API key，仅返回官方域名候选摘要。
- 固定请求、追加执行结果及来源登记关联；未知执行状态、失败、限流和无结果分别显示，不自动重试或伪造结论。
- 人工核对原文和判断时点后才能登记准确引文；候选摘要不会自动填入法条引文。保留原记录，登记幂等，变化需要追加新记录。
- 新来源沿既有审查版本更新机制使旧批准需复核，不关闭意见、不批准交付；不自动抓取原文或评定法律效力。
- 记录北大法宝、元典、官方入口、SharePoint、文件目录和 Playwright 的一手资料、接入边界与未知项；这些候选未实际连接。
- 同步公开源码授权、MIT许可、匿名克隆和默认分支的实际结果；保留先前权限阻塞为历史，后续以GitHub当前默认分支接手。
