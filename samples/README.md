# 虚构合同演示样例

所有主体、金额、签约安排、审批附件均为演示数据，不是真实客户资料，也不是可签署的合同模板。

| 版本 | 第5.2条付款期限 | 第8.2条解除通知对象 | 第4.1条所要求的附件一 |
| --- | --- | --- | --- |
| `investment-v1-initial` 初稿 | 10个工作日 | 甲方即示例投资合伙企业 | 有虚构董事会批准文字 |
| `investment-v2-counterparty` 对方版 | 5个工作日 | 改为示例管理公司 | 缺失 |
| `investment-v3-revision` 修订稿 | 改回10个工作日 | 仍为示例管理公司 | 仍缺失 |

三个版本均提供 DOCX、UTF-8 Markdown 和可提取文字的 PDF。正文修改前后应上传为不同版本。第三版只修改付款期限，不能据此自动关闭解除通知对象与缺失附件的审核问题；付款期限问题也需要法务人工核验和关闭。

`fictional-scan-needs-ocr.pdf` 为无文字层的图片式虚构样例。用于验证“待 OCR”提示，不应据此生成空白或不完整的对外稿。

在仓库根目录执行 `python -m samples.generate` 可重新生成样例。DOCX 包时间固定仅为保证虚构样例哈希可复现，不代表真实创建或签署日期。

## 已实现范围与限制

- DOCX：归档原始字节；提取普通段落及表格文字，标识修订、批注、隐藏内容、外部关系和复杂构件。新建清洁文本快照，不重建原稿版式和 Word 修订，不复制图片、页眉页脚、脚注、签名或复杂自动编号。原件继续在 Word 中编辑，随后上传为新版本。
- PDF：归档原始字节；有限大小与页数内提取标准文字层；无可靠文字、缺少文字的页面标待 OCR。OCR、签章验证、加密 PDF 解密和复杂嵌套表单不在首版范围。导出为新建中文文本 PDF 快照，使用标准 CJK 字体，需要阅读器支持标准中文字体。
- Markdown：归档及 UTF-8 文本解析；导出结构化意见和正文快照。按文字展示，不执行 HTML。含 HTML 注释或活动标签的交付件不能通过结构检查。
- 对外文件的结构检查覆盖常见批注、修订、显式隐藏文字、作者/自定义元数据、外部关系及嵌入对象等，不能证明正文没有敏感信息，也不能替代逐条人工复核和批准。
