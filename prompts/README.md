# 法务工作动作与提示词 V0.3

本目录保留10个动作的设计。“意见改写”专用流程读取 `shared.md` 和 `03-opinion-rewrite.md`，填入固定资料并生成提示词。V0.3 另写入本项目关键词搜索、公开问题准备、可选搜索与人工法源记录；这些是确定性接口和人工表单，尚未自动执行 `08-legal-question.md`。其他动作仍未接入。`catalog.json` 记录部分实现状态，不是已经驱动全部界面的通用执行器。

应用标识为 `0.3.0-dev`；实现说明见 [意见改写 V0.2](../docs/OPINION-REWRITE-V0.2.md)和[检索 V0.3](../docs/RETRIEVAL-V0.3.md)。本轮未调用 Gemini／Claude 或搜索 API，未运行测试、启动应用或做模型评测。普通资料默认只准备提示词及手工草稿；明确的虚构样例可选择非模型离线示例。

`catalog.json` 定义10个工作动作；首批4个为合同首审、来稿复核、意见改写、审批材料。`shared.md` 是所有任务的共同约束；对应任务文件给出具体产物。`playbook-example.json` 仅为虚构、待确认的审查标准示例，绝不是公司政策。

意见改写流程读取共同约束和任务模板，再从工作台生成固定的 `context_snapshot`。双大括号变量由系统填充，使用者选择读者和语气。一次只处理一个用途；模板中的“对照”能力尚未做成同时生成三版的界面。任何未填资料都表示缺项，不得编造。先展示用了哪些资料，保存草稿后再由法务采纳。

这些模板可供法务在已获准处理对应资料的AI环境中使用。提供复制或本地资料包，不代表获准向任意外部AI发送真实合同。法律检索专用动作仅输出去标识化问题；与合同审查模型的数据授权分开。

## 资料包约定

完整设计建议 `context_snapshot` 包含任务与提示词版本、项目与我方角色、法域/判断时点、材料范围、已确认事实及来源、固定合同版本/摘要、所需正文或条款、历史问题、法源、获准审查标准、解析警告、未知项和数据处理范围。本次意见改写实际使用已有项目、意见、原始／当前版本与条款、法源及未知项；项目事实卡和公司标准库尚未实现，不能据此宣称资料完整。

不是每个动作都需要整份合同：意见改写只带该问题和关联条款；审批摘要主要带事实、问题与附件清单；来稿复核带两版差异、未决问题与关联条款。必要材料不足时明确影响范围。

## 输出与回写

仅准备资料的任务为 `prepared`；有文字草稿后为 `draft`；人工采纳后为 `adopted`。意见改写保存独立的草稿与采用记录，不覆盖原意见或改变问题状态。实际依据、合同版本或处理状态变化时必须重新准备；仅采纳另一种用途的表达不会使已有表达互相过期。每次采纳仍更新审查版本，使旧交付批准需要复核。文字差异和含义说明不能替代人工语义判断。

法律风险判断、条款实质修改、意见关闭、例外接受和交付批准仍分别由法务／有权角色确认。正文修改后形成新文件版本；本次不写回 Word 原件。模型不直接调用关闭意见或批准交付接口。
