## 一条命令启动

需要 Python 3.11+（V0.1 历史运行环境：Python 3.12.14），macOS / Linux 的 Bash。以下启动说明留给恢复运行安排后使用；本轮没有执行。解压交付包，进入 `fund-legal-workbench` 目录：

```bash
bash start.sh
```

首次启动会创建 `.venv` 并安装 `requirements.txt` 中固定版本的依赖，需要能访问 Python 包源。随后打开 **http://127.0.0.1:8765**。不需要 Node、Docker、数据库服务或模型账号。按 `Ctrl+C` 停止；再启动会保留本机台账和原件。

已有依赖的环境也可运行 `python run.py`。服务固定绑定 `127.0.0.1`；不提供公网绑定选项。可用 `FWB_PORT` 更换本机端口，`FWB_DATA_DIR` 指定数据目录。默认数据在 `.data/`，已经被 Git 忽略。

**历史验证范围：**V0.1 曾在已有依赖的执行环境启动 Uvicorn，并通过真实 HTTP 请求取到健康状态、首页、JavaScript 和创建演示项目响应。V0.2/V0.3 尚未重新执行，不表示当前代码或目标 Mac 已通过启动检查。

## V0.3 查资料与公开法源（代码已写入，待运行）

在“法源”内使用三个入口：

- **查当前项目资料：**按关键词找已导入的合同文字、审核意见、法源台账与采用表达；默认当前版本，可包含历史。结果带版本或记录位置。待 OCR 文件会提示覆盖不足，不会转而查询电脑或公司系统。
- **查公开法源：**另行输入去标识化问题，选择判断时点和用途。默认“准备官方检索”，仅记录问题并提供官方跳转；显式启用搜索后，可向 Tavily 发送该问题。候选均标“搜索摘要，待核对原文”，不自动变成法条引文或审查结论。
- **连接与范围：**显示本机配置及未接入能力。北大法宝、元典、公司库、只读目录与浏览器均列为候选或未授权，不伪装成实际连通。

人工打开原文后，可从检索记录录入准确引文、类别、公布/生效日期、效力状态与核验说明，并确认法域和判断时点。系统保留候选关联和人工确认时间；这不表示应用抓取过原文。法源追加会更新审查版本，使此前的外稿批准需要复核，不会关闭意见。

服务端配置 `FWB_PUBLIC_SEARCH_MODE` 支持 `disabled`（默认）、`keyless`、`api_key`。API key 模式只从 `FWB_TAVILY_API_KEY` 读取密钥；不要把值放入代码、聊天或前端。无密钥模式也会把抽象问题发送给第三方，仍需适用的数据授权和显式提交。用户当前暂缓验证，此处仅说明配置，不是要求现在调用。详见[实现边界与接口](docs/RETRIEVAL-V0.3.md)、[法律 MCP 调研](docs/LEGAL-SOURCE-CONNECTORS-RESEARCH.md)及[检索架构](docs/RETRIEVAL-ARCHITECTURE.md)。

## V0.2 意见改写使用路径（代码已写入，待运行）

在“审核意见”选择一条意见，点击“改写 / 查看表达”；选择“内部法务／业务沟通／对方批注”和“简洁／温和／坚定”，再点击“准备这次改写”。系统为本次工作固定原意见、原始与当前版本、相关条款、依据及缺项，不在处理过程中替换资料。

- **准备资料与提示词：**默认路径，不调用模型。可复制已整理的提示词，或手工录入草稿；真实资料只能在已获准的环境中处理。
- **离线演示：**仅对内置虚构样例的预设问题提供明确标记的示例文字，不作为 Gemini／Claude 的输出或效果证明。
- **保存与采纳：**手工编辑文字并记录含义变化说明，每次保存新增草稿。法务确认语义；对方批注还须确认披露范围，填写采纳说明后新增采用记录。原意见、原引文和问题状态继续保留。
- **资料变化：**合同版本、原意见、处理状态或依据等审查资料变化后，旧任务需重新准备，不能继续采纳过期草稿。仅采纳另一种用途的表达，不会使已有表达或待采纳草稿互相过期；每次采纳仍更新审查版本，使此前对外稿批准需要重新复核。采纳不等于关闭问题或批准交付。

生成内部审核清单时，DOCX、PDF、MD 路径会先保留原建议，再附与导出版本一致、仍有效的最新已采用表达及内部说明。对外清洁合同稿的正文路径保持独立，不混入这些表达、内部说明或采用记录。此新增导出行为同样尚未运行验证。

尚未点击“保存为新草稿”的输入只暂存在当前页面内存；关闭或刷新浏览器前需保存，不提供跨刷新恢复承诺。

本次不提供自动语义保证、公司审批权限或 Word 原件写回。复制的是选定用途的意见文字；Word 中的编辑继续由法务完成并上传新版本。完整实现边界见[意见改写说明](docs/OPINION-REWRITE-V0.2.md)。

## V0.1 原有演示链路（后续恢复验证时使用）

1. 首页点击“体验虚构投资项目”或“打开虚构演示”，生成「青禾科技 · A轮投资（虚构）」与投资协议初稿 V1。也可以新建空项目/合同，上传 `samples/` 中的虚构文件。
2. 在合同页载入对方版 V2，查看 V1/V2 差异。第 5.2 条付款期限从 10 个工作日改为 5 个工作日；第 8.2 条解除通知对象从甲方改为管理公司；附件一的虚构董事会批准决议被移除。
3. 点击“提取演示建议”，查看三条草稿意见。其中第 8.2 条挂接《民法典》第 565 条官方出处和准确引文；第 5.2 条与审批附件依据为合同约定。也可手工添加意见，系统检查引文确实位于该版本指定条款及法源记录中。
4. 载入修订稿 V3。期限恢复为 10 个工作日；通知对象与审批附件仍未解决。三条意见仍待人确认，期限意见显示旧引文与新版条款差异，不自动结案。可切换全部版本历史。
5. 进入交付物，生成 **内部审核清单** 与 **对外清洁阅读稿**。支持 DOCX、PDF、MD；内部稿带问题和依据，对外稿不带内部审核意见。
6. 对外稿暂处于待批准状态。批准弹窗提供正文预览和 **内部审阅包（待批准）**；包内是拟交付产物的精确字节及未批准说明。用 Word/PDF 阅读器打开核对实际内容、布局、源修订、隐藏信息和附件。
7. 填写批准说明，人工确认；有未结问题时须额外明确接受“保留问题继续谈判”。批准不等于意见结案，也不等于可以签署。只有有效批准后才出现对外交付下载。
8. 修改版本或审查记录后，之前的批准失效，下载返回 409。历史原件始终可以按原字节取回；归档可恢复，没有签署件/意见的普通硬删入口。

内置建议是确定性演示规则，**不是 Gemini/Claude 的模型输出**；规则只覆盖标记的虚构样例，空结果不代表无风险。所有合同主体、金额和事实均为虚构；法源条文是真实核验资料，二者明确分开。

## 已实现与未做的文件路径

| 格式 | 导入与归档 | 首版解析/比较 | 已实现导出 | 未做与限制 |
| --- | --- | --- | --- | --- |
| Word `.docx` | 保存原始字节、SHA-256、新版本；原修订与批注保留在原件 | 段落与表格文字；修订按新增保留/删除排除的阅读视图提取，并提示人工核对；文本差异 | 新建内部审核清单、对外清洁阅读稿 | 不重建 Word 修订；不保留原版式、图片、脚注、复杂编号或签章；不做在线编辑。复杂结构只作辅助阅读 |
| PDF | 保存原件；签署件仅作为签署原件归档，不据其重建清洁稿 | 可提取文字；无可靠文字或部分页面无法提取时标 `needs_ocr`，阻止差异/清洁导出 | 新建可阅读的文字快照、内部清单；可下载签署原件 | 不做 OCR、不验证电子签名、不复原复杂版式；生成中文 PDF 依赖阅读器标准 CJK 支持 |
| Markdown `.md` | 保存 UTF-8 原件与历史版本 | 纯文本与条款定位、文本差异 | 结构化内部意见清单、对外文本稿 | 不做 Word 布局往返；含原始 HTML 的外稿不通过结构检查 |

支持文件最大 15MB。解析器对 ZIP 解压尺寸/压缩比/路径、XML 实体和深度、PDF 页数/文本流等设限；损坏、加密或不支持安全解析的文件会明确拒绝，并不会悄悄当成成功解析。结构检查不等于杀毒、完整内容脱敏或法律正确性保证。

## 三个公司对接入口

静态接口契约 [docs/openapi.json](docs/openapi.json) 是此前由 V0.1 路由生成的快照，仍覆盖以下三个公司接口；本轮未运行应用重新生成，因此不包含新增的本地意见改写与检索接口。新增接口说明见[意见改写说明](docs/OPINION-REWRITE-V0.2.md)和[检索实现说明](docs/RETRIEVAL-V0.3.md)，恢复启动后 `/openapi.json` 将由当时实际路由提供。

| 方法与路径 | 范围 | 行为 |
| --- | --- | --- |
| `GET /api/integration/projects/{pid}/contracts` | `contracts:read` | 按项目授权列合同/版本元信息；不返回存储路径 |
| `POST /api/integration/projects/{pid}/contracts/{cid}/versions` | `versions:write` | multipart 导入新版本；必须有 `Idempotency-Key`；相同键不同内容/参数返回 409 |
| `GET /api/integration/projects/{pid}/deliverables/{did}/download` | `deliverables:read` | 只下载本项目有效批准的对外件；未批准 403、内部稿 404、批准失效 409 |

默认三接口返回 503，表示没有配置公司连接。V0.1 测试曾通过注入临时随机令牌验证项目及 scope 边界，本轮未重跑。若后续用环境变量 `FWB_INTEGRATION_TOKENS` 配置，值为 `{ "运行时生成的令牌": { "projects": ["项目ID"], "scopes": ["contracts:read"] } }` 这样的映射；不要把真实值写进仓库、日志或聊天。

这只是集成接口的授权边界。普通 `/api/projects/` 是本机单人入口，没有企业登录/RBAC，不能据此宣称整个应用已具备企业隔离。对外接口与本机内部审阅包用途不同；内部审阅包不会改变批准状态，不提供公司接口下载。UI和源文件不能充当防止人手动外发的DLP系统。

## 架构与选择

采用同源静态界面 + FastAPI + SQLite + `BlobStore` 接口。原件按摘要保存；版本、法源快照与审计追加；当前版指针、意见状态和批准状态可变化。存储接口、审查 Provider 和法源准备入口分别保留替换边界。SQLite 单人本地适配不代表已经满足公司级多用户并发。

调研了既有企业文档库、Nextcloud Files/Tables、OpenContracts 和轻量自建。当前采用单体是为了先验证 Word 工作习惯与审查闭环；没有把任一产品当成完整 CLM。Nextcloud 历史保留需单独配置核验；OpenContracts 当前上游许可为 MIT、依赖体量较大，保留作为解析/标注候选；北大法宝确有官方 MCP/CLI 服务，但本账号授权、覆盖、限额、更新与留存未验，不启用调用。详见 [研究记录](docs/RESEARCH.md)、[架构决策](docs/ADR-001.md)。
